**Scale:** L / Med

## Goal

Extract framework-neutral core modules from casehub-desiredstate so the
runtime, graph declaration surfaces (annotations, YAML, TypeScript DSL),
and persistence can be embedded in both Quarkus and Spring Boot
applications. Follows the established platform pattern
(casehubio/parent#469).

@ApplicationScoped
public class RuntimeBeans {

    @Produces @ApplicationScoped
    TransitionPlanner planner(NodeProvisionerRouter router,
                              ReconciliationStateStore stateStore,
                              FaultCountStore faultCountStore) {
        return new TransitionPlanner(router, stateStore, faultCountStore);
    }

    @Produces @ApplicationScoped

                                        FaultCountStore store) {
        return new FaultPolicyEngine(policies.stream().toList(), store);

                                          FaultPolicyEngine fpe,

                                          Event<CloudEvent> events,
                                          Instance<GlobalReconciliationListener> listeners) {
        return new ReconciliationLoop(planner, fpe, executor, router,
                events::fire, listeners.stream().toList());
    }

    // ... similar for remaining core POJOs
}

## annotations/spring/ — Jandex Scanning

```java
@AutoConfiguration
@ConditionalOnClass(GoalCompilerFactory.class)
public class DesiredStateAnnotationsAutoConfiguration
        implements SmartInitializingSingleton {

    private final GenericApplicationContext context;

    @Override
    public void afterSingletonsInstantiated() {
        // 1. Read META-INF/jandex.idx from all classpath JARs
        // 2. Scan for @DesiredState, @DeclareNode, @GraphRule, etc.
        // 3. Build GraphDescriptor records (same logic as deployment)
        // 4. Validate (duplicate IDs, dangling deps, cycles)
        // 5. For @DesiredState interfaces: create JDK Proxy instance
        // 6. Call GoalCompilerFactory.create(descriptor)
        // 7. Register as named bean via context.registerBean()
    }
}
```

Validation runs at startup — same checks as the Quarkus deployment
module but at runtime rather than build time. Failures are fast
(application fails to start with clear error messages).

### Descriptor extraction reuse

The Quarkus deployment module builds `GraphDescriptor` from Jandex
`IndexView`. This logic is currently interleaved with `@BuildStep`
methods. Extract the pure descriptor-building logic (Jandex → descriptor
records) into annotations/core/ as a `DescriptorScanner` utility class.
Both the Quarkus deployment and Spring auto-config use the same scanner.

The Quarkus deployment module gains a dependency on annotations/core/
for the shared scanner. This is safe — annotations/core/ is pure Java +
Jandex (no Quarkus runtime dependency). The deployment module already
depends on Jandex transitively.

## Spring Generation

`runtime-spring/` is generated by the platform's `spring-generator`
Maven plugin — same approach as all other platform modules. The
generator scans `@Produces` methods in `RuntimeBeans` via Jandex and
generates `@AutoConfiguration` classes.

The surface-specific Spring modules (annotations/spring/, yaml/spring/,
etc.) are **hand-written** because they contain startup scanning logic
that the generator cannot produce.
